=== mote reliability: recovery evidence ===

Curated results from three runs: the systemd restart policy on a workstation,
and the startup gate plus per-node respawn on the real robot (auldbot,
Raspberry Pi 5, aarch64, 2026-07-26). See README.md in this directory.

--- 2. startup self-check gate (auldbot) -------------------------------------

Servos unpowered — the gate must block bringup:
  [PASS] servo_bus: /dev/mote_servos present and openable
  [FAIL] servo_ping: id=7 MISSING; id=9 MISSING; FAIL: 2/2 servos did not respond
  [PASS] lidar, camera, disk_space, clock, robot_yaml, active_site
  self-check: NOT READY — mission blocked                       exit=1

  Cross-checked against the pre-existing servo_debug `ping 1 9`, which also
  found zero responders: a true negative, not a tool bug.

  Side effect worth recording: with the bus unresponsive each read() blocks
  ~200 ms per servo, so controller_manager overran its 50 Hz loop ("the loop
  took 601 ms") and /joint_states fell to ~1.6 Hz. The health monitor reported
  FAULT while the driver itself only logged warnings.

  [PASS] servo_bus, lidar, camera, disk_space, clock, robot_yaml, active_site

Scenario C — kill ros2_control_node: FIRST RUN FAILED and found a real defect.
  respawn fired, but re-running the OnProcessStart spawner actions raised
  "ExecuteLocal action 'spawner-11': executed more than once". That exception
  aborted the launch and SIGINT'd every other node — the lidar and camera died
  too and nothing recovered. A launch action may only ever be executed once.
  Fixed by building fresh spawner actions per start (mote_bringup/launch_utils.py).

--- Not yet verified on the robot -------------------------------------------

* Service-level restart of the installed units, and the journald drop-in:
  needs `pixi run install-systemd` (root). The units pass
  `systemd-analyze verify`, and their restart policy is proven in run 1 above.
* A true USB unplug rather than a node kill, which also needs root.
* chaos_restart.sh against the full nav stack including controller_server.
